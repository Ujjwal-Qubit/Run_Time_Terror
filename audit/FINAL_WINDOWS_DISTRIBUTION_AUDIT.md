## 3. Standalone Assessment: Single-EXE vs Full Directory

### Empirical Test 1: Copying ONLY `LumiTrack.exe`
To test whether `LumiTrack.exe` can be distributed as a standalone single file without `_internal/`, the executable was copied to an isolated temporary directory (`$env:TEMP\test_standalone_exe_only\LumiTrack.exe`) and invoked:

```powershell
$proc = Start-Process "$env:TEMP\test_standalone_exe_only\LumiTrack.exe" -ArgumentList "--validate"
```

**Result: IMMEDIATE CRASH**
```
[PYI-18040:ERROR] Failed to load Python DLL 'C:\Users\...\test_standalone_exe_only\_internal\python311.dll'.
LoadLibrary: The specified module could not be found.
Exit Code: -1
```

### Technical Root Cause
In PyInstaller 6+, `onedir` builds decouple the bootloader stub (`LumiTrack.exe`, ~5 MB) from the application archive and libraries (`_internal/`, ~276 MB). The executable's PE entrypoint expects `.\_internal\python311.dll` to be present relative to `sys.executable`.

### Verdict
**`LumiTrack.exe` is NOT a self-contained single-file executable.**  
Distributing only `LumiTrack.exe` to an evaluator will result in immediate failure on any machine. The evaluator MUST receive either the complete directory structure, an archive containing the structure, or an installer that sets up the directory structure.

## 4. Comprehensive Runtime Dependency Breakdown

Every runtime dependency required by `dist/LumiTrack` was analyzed via PE header parsing (`pefile`), AST import inspection, and dynamic trace monitoring.

### 4.1 Dynamic Link Libraries (DLLs)
DLLs fall into three distinct classes:

#### Class A: Bundled Inside `_internal/` (Self-Contained)
- **Universal C Runtime (UCRT):** `ucrtbase.dll`, `api-ms-win-crt-*.dll` (14 API sets), `api-ms-win-core-*.dll` (28 API sets).
- **C/C++ Runtimes:** `VCRUNTIME140.dll` (119 KB), `VCRUNTIME140_1.dll` (49.5 KB).
- **Python Runtime:** `python311.dll` (5.80 MB), `python3.dll` (67 KB).
- **Cryptography & Security:** `libcrypto-3.dll` (5.19 MB), `libssl-3.dll` (787 KB), `libffi-8.dll` (39 KB).
- **Video & Acceleration:** `opencv_videoio_ffmpeg4140_64.dll`, OpenBLAS `libscipy_openblas64_*.dll`.

#### Class B: Windows Host OS Native APIs (Guaranteed on Windows 10/11)
The following 23 DLLs are imported by `LumiTrack.exe` and compiled `.pyd` modules, but are native OS system components present on every Windows 10 and Windows 11 installation:
- `KERNEL32.dll`, `USER32.dll`, `GDI32.dll`, `ADVAPI32.dll`, `SHELL32.dll`, `OLE32.dll`, `OLEAUT32.dll`
- `WS2_32.dll` (Sockets), `VERSION.dll`, `bcrypt.dll`, `crypt32.dll`, `dwmapi.dll` (Desktop Window Manager)
- `gdiplus.dll`, `imm32.dll`, `mpr.dll`, `netapi32.dll`, `shcore.dll`, `shlwapi.dll`, `userenv.dll`, `uxtheme.dll`, `winmm.dll`

#### Class C: Potential Clean-Machine Risk: `MSVCP140.dll`
- **Dependency:** `cv2.pyd` and `shiboken6` import `MSVCP140.dll` (Microsoft Visual C++ 2015–2022 C++ Standard Library).
- **Status in Distribution:** 
  - `MSVCP140.dll` is present in `_internal\PySide6\MSVCP140.dll` and `_internal\shiboken6\MSVCP140.dll`.
  - It is **NOT** present at the root of `_internal\`.
- **Clean-Machine Impact:** On a freshly formatted Windows machine that has never installed Visual Studio or third-party desktop software, `C:\Windows\System32\msvcp140.dll` may not exist. If Windows DLL search cannot locate `msvcp140.dll`, importing OpenCV may fail.
- **Resolution in Installer:** An installer can safely place `MSVCP140.dll` into `{app}\_internal` or run the official Microsoft VC++ Redistributable (`vcredist_x64.exe`) silently during installation.

### 4.2 Qt / PySide6 Components
- **Core Qt Framework:** `QtCore`, `QtGui`, `QtWidgets` bundled as `.pyd` extensions in `_internal/PySide6`.
- **Platform Plugin:** `_internal/PySide6/plugins/platforms/qwindows.dll` (Verified present). Required for Qt windowing on Windows.
- **Excluded Modules:** Heavy unused Qt modules (QtWebEngine, QtQuick, Qt3D, QtNetworkAuth) are excluded, saving over 400 MB.

### 4.3 Model Files & Neural Network Weights
All required machine learning weights are bundled inside `_internal/` and resolved at runtime via `sys._MEIPASS`:
1. `models/candidate_classifier/v001/mlp_weights.json` (11-feature pure-NumPy MLP weights)
2. `models/candidate_classifier/v001/mlp_metadata.json` (Architecture, hyperparameter metadata)
3. `models/candidate_classifier/v001/normalization_params.json` (Input standardization parameters)
4. `models/temporal_predictor/v001/model_params.json` (Temporal trajectory predictor)
5. `models/temporal_predictor/v001/model_metadata.json` (Predictor metadata)
6. `lr_model.json` (Fallback 4-feature classifier weights)

### 4.4 Scenario & Configuration Files
- **Scenarios:** `scenarios/scenario_1_linear.json`, `scenario_2_circular.json`, `scenario_3_zigzag.json`, `scenario_4_random_walk.json`.
- **Configuration Defaults:** Self-contained in compiled bytecode (`src.config.defaults`). Evaluators can provide custom JSON configs via `--config <path>`.

### 4.5 Tracking Algorithm Plugins
- **Location:** `_internal/src/plugins/algorithms/baseline_tracker/`
- **Contents:** `manifest.json` and `baseline_tracker.py`.
- **Discovery:** Verified via `PluginLoader` in standalone executable. Custom external plugins can be loaded at runtime via `--plugins-dir <path>`.

### 4.6 File System & Working Directory Assumptions
- **Output Destination:** `ConfigManager` sets `LOG_OUTPUT_DIR = "output"` relative to the current working directory (`os.getcwd()`).
- **AI Scenarios Destination:** `ai_scenario.py` writes to `"output/ai_scenarios"` and `"scenarios/ai_generated"`.
- **Permission Sensitivity:** If installed into `C:\Program Files\LumiTrack\` and executed by a non-administrator, Windows blocks writing to `Program Files`. The application would fail unless run as Administrator or installed into a user-writable location (`%LOCALAPPDATA%\Programs\LumiTrack`).

### 7.4 Uninstallation & Clean Directory Removal
When executing `unins000.exe` from `$env:TEMP\inno_installed_app`, Windows Defender Application Control (WDAC) / Attack Surface Reduction (ASR) policy triggered:
`An Application Control policy has blocked this file.`

#### Security & Policy Finding:
- Modern Windows 10/11 environments enforce Software Restriction / ASR rules that forbid running newly dropped or unsigned executables from `%TEMP%` subdirectories.
- This reinforces the recommendation to:
  1. Default the installation path to standard user application directories (`{localappdata}\Programs\LumiTrack`) rather than temporary directories.
  2. Provide the dual-deliverable strategy (Installer + Portable ZIP), so evaluators on corporate/institutional Windows systems with strict WDAC / AppLocker execution policies have an immediate, unblocked extraction path.

## 10. Remaining Blockers & Implementation Action Plan

### Blocker 1: Console Window Spawning alongside GUI
- **Current State:** `lumitrack.spec` specifies `console=True`. When double-clicking `LumiTrack.exe`, a black CMD console window opens behind the Qt window.
- **Impact:** While harmless, it looks less polished for a non-technical evaluator.
- **Solution:** 
  - Option 1: Keep `console=True` because SIH PS evaluation specifically includes CLI benchmarks and `--validate` commands.
  - Option 2: Provide two binaries: `LumiTrack.exe` (`console=False` for clean GUI launch) and `LumiTrack-CLI.exe` (`console=True` for CLI commands).
  - *Recommendation:* Keep `console=True` or use Windows `AttachConsole` API so one binary serves both GUI and CLI smoothly.

### Blocker 2: `MSVCP140.dll` Placement
- **Current State:** `MSVCP140.dll` is inside `_internal\PySide6\`, but not `_internal\` root.
- **Impact:** Risk of `ImportError` on a clean Windows machine without VC++ 2015-2022 redistributable.
- **Solution:** In the installer script or `lumitrack.spec`, ensure `MSVCP140.dll` is placed in `_internal\` root alongside `VCRUNTIME140.dll`.

### Blocker 3: Output Directory Permissions
- **Current State:** If installed in `C:\Program Files`, default `./output` writing fails for non-admins.
- **Solution:** Using `PrivilegesRequired=lowest` and installing into `{localappdata}\Programs\LumiTrack` completely eliminates this blocker.
