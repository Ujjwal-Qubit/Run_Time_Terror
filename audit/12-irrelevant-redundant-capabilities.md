## 1. Executive Summary

A significant fraction of the local codebase consists of accidental complexity, architectural theater, and redundant technology stacks that dilute engineering focus and bloat the system footprint without advancing the core physical mission: **high-bandwidth, robust coarse alignment of optical communication terminals under severe disturbances**.

We identify and quantify the primary candidates for immediate deprecation and retirement.

---

## 2. Inventory of Candidates for Retirement

### 2.1 The React 18 / Vite / Three.js Frontend (`frontend/`)
- **Nature of Asset**: A complete single-page web application featuring React 18, Vite, Three.js, Lucide icons, and Tailwind CSS.
- **Lines of Code / Weight**: Over 15,000 lines of TypeScript/JSX, requiring a `node_modules` cache of $>250\text{ MB}$.
- **Forensic Assessment**:
  - The Problem Statement explicitly mandates a **standalone desktop application** (`.exe`) runnable offline on Windows.
  - The repository already contains a native, hardware-accelerated **PySide6 (Qt) desktop application** in `src/app/gui/`.
  - Maintaining a parallel web frontend introduces a dual-frontend maintenance nightmare: any metric or control law added to Qt must be re-implemented in React/TypeScript.
  - In a real FSOC terminal (ground station or mobile vehicle), operators do not launch a Node.js development server to steer a gimbal.
- **Verdict**: **REDUNDANT / RETIRE**. All frontend efforts should consolidate strictly into a single high-performance desktop UI (or direct headless daemon).

### 2.2 The FastAPI / Uvicorn / WebSockets Server (`src/api/server.py`)
- **Nature of Asset**: A REST and WebSocket API server running on port 8000.
- **Forensic Assessment**:
  - The server was created solely to serve frames and telemetry to the React frontend.
  - It converts NumPy image arrays into compressed JPEG or Base64 strings, broadcasts them over WebSockets, and runs synchronous image processing within an `asyncio` event loop.
  - This introduces $15\text{--}40\text{ ms}$ of serialization and transport latency, saturates the CPU, and creates a severe network vulnerability (wildcard CORS, zero authentication).
- **Verdict**: **REDUNDANT / RETIRE**. If remote telemetry is ever needed, use a lightweight, binary-encoded gRPC or UDP Protobuf stream.

### 2.3 The "AI Natural Language Interpretation Engine" (`src/evaluation/ai_scenario.py`)
- **Nature of Asset**: A module claiming to use "Natural Language AI" to interpret operator prompts into benchmark scenarios.
- **Forensic Assessment**:
  - Inspection of `ai_scenario.py` reveals that the "AI" consists entirely of 20 lines of basic Python regex substring searches:
    ```python
    if re.search(r"\b(spiral|lissajous|circle)\b", prompt, re.I):
        scenario["trajectory"] = "spiral"
    if re.search(r"\b(fog|smoke|haze)\b", prompt, re.I):
        scenario["visibility"] = 0.4
    ```
  - Branding this as "AI" is deceptive and constitutes pure hackathon theater.
  - Parameterized JSON/YAML scenario profiles or clean CLI flags are dramatically more expressive, robust, and reproducible.
- **Verdict**: **THEATER / REPLACE**. Replace with structured scenario schemas (Pydantic / YAML) with full parameter validation.

### 2.4 The AST-Based "Ground-Truth Firewall" (`src/evaluation/firewall.py`)
- **Nature of Asset**: An AST (Abstract Syntax Tree) analyzer that scans the tracker module source files to confirm no `import src.simulator` statements exist.
- **Forensic Assessment**:
  - While intellectually clever, building an in-tree AST static analyzer is an over-engineered meta-verification tool for a 5,000-line codebase.
  - Normal software architecture enforces boundaries via interface design, package dependency isolation, or standard linter rules (`flake8-import-order`, `ruff`).
  - The AST firewall tests add runtime overhead and give a false sense of security while ignoring real physical failure modes.
- **Verdict**: **OVER-ENGINEERED / SIMPLIFY**. Enforce separation through clean interface encapsulation (`ITracker`, `ITerminalSimulator`) rather than AST code reflection.

### 2.5 The Secondary Machine Learning Module (`src/aiml/`)
- **Nature of Asset**: An 11-feature candidate classifier and a 2-layer MLP temporal model with synthetic training scripts.
- **Forensic Assessment**:
  - The models were trained on 30 synthetic data points generated by NumPy random generators.
  - In `src/tracker/baseline_tracker.py`, these models are **disabled by default**:
    ```python
    self._aiml_candidate_enabled = False
    self._aiml_temporal_enabled = False
    ```
  - The models are dead weight: they do not run in default benchmarks, but pull in `scikit-learn` ($150\text{ MB}$) as a hard dependency.
- **Verdict**: **DEAD CODE / PURGE**. Remove the dummy synthetic models; either implement a real deep neural network (e.g. NanoTrack/ONNX) or rely entirely on robust classical centroiding.

### 2.6 The Abstract Single-Plugin Framework (`src/plugin/`)
- **Nature of Asset**: An abstract plugin architecture with registries, hooks, and dynamic loading.
- **Forensic Assessment**:
  - The entire repository contains exactly **one** trivial plugin (`dummy_plugin.py`).
  - Developing a dynamic plugin system for a project with one implementation of each component is classic speculative generality (YAGNI violation).
- **Verdict**: **SPECULATIVE GENERALITY / REMOVE**. Replace with direct dependency injection or simple functional composition.
